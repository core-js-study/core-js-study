# 3장. this
## 상황에 따라 달라지는 this
- JS에서 this는 기본적으로 실행 컨텍스트가 생성될 때 함께 결정된다.
  - 실행 컨텍스트는 함수가 실행될 때 결정됨
  - 즉, this도 함수를 호출할 때 결정된다

<br>

### 3-1-1. 전역 공간에서의 this
- 전역 공간에서의 this는 전역 객체를 가리킨다.
  - 생각해보면, 전역 컨텍스트를 생성하는 주체가 전역 객체이기 때문이다.
- 전역 객체는 JS 런타임 환경에 따라 다른 이름과 정보를 가지고 있다.
  - JS 런타임 환경?? ES6, ES5같은걸 말하는건가?
  - 아 브라우저인지, Node.js 인지를 의미하는 것이다.
    - 브라우저에서의 전역 객체는 window
    - Node.js 환경에서는 global
#### 전역 변수를 선언하면, JS엔진은 이를 전역 객체의 프로퍼티로 할당한다.
```js
var a = 1;
console.log(a); // 1
console.log(window.a); // 1
console.log(this.a); // 1
```
- 이런식으로 전역공간에서 선언한 변수인 a에 1을 할당했을 뿐
  - 그런데, window.a와 this.a 모두 1이 출력된다.
- 왜일까?
#### JS의 모든 변수는 실은 특정 객체의 프로퍼티로서 동작하기 때문이다.
- 변수를 선언하더라도 JS엔진은 특정 객체의 프로퍼티로 인식한다
  - 여기서 말하는 '특정 객체'란 `LexicalEnvironment`이다.
- 실행 컨텍스트는 변수를 수집해서 LE의 프로퍼티로 저장한다.
  - 이후 어떤 변수를 호출하면 LE를 조회해서 일치하는 프로퍼티가 있을 경우 그 값을 반환한다.

<br>

#### 전역변수를 선언하면 자동으로 전역객체의 프로퍼티로 할당한다 X
#### 전역변수를 선언하면 JS 엔진은 이를 전역객체의 프로퍼티로 할당한다 O
- 그렇다면, var로 변수를 선언하는 대신 window의 프로퍼티에 직접 할당하더라도 결과적으로 var로 선언한 것과 똑같이 동작할까?
  - 대부분의 경우 이 말이 맞다.
  - 그러나 삭제 명령에 대해서는 다르게 동작한다.
```js
var a = 1;
delete window.a; // false
console.log(a, window.a, this.a); // 1 1 1

var b = 2;
delete b; // false
console.log(b, window.b, this.b); // 2 2 2

window.c = 3;
delete window.c; // true
console.log(c, window.c, this.c); // Uncaught ReferenceError: c is not defined

window.d = 4;
delete d; // true
console.log(d, window.d, this.d); // Uncaught ReferenceError: d is not defined
```
- 변수에 delete 연산자는 이상해 보일 수 있지만, window.변수 라고 생각하면 된다.
- 처음부터 전역객체의 프로퍼티로 할당한 경우에는 삭제가 되지만, 전역 변수로 선언한 경우에는 삭제가 되지 않는다.
  - 이는 사용자가 의도치 않게 삭제하는 것을 방지하는 차원에서 마련된 방어 전략인 듯 하다.

### 3-1-2 메서드로서 호출할 때 그 메서드 내부에서의 this
#### 함수 vs 메서드
- 함수는 그 자체로 독립적인 기능을 수행한다
- 메서드는 자신을 호출한 대상 객체에 관한 동작을 수행한다.
- js는 상황별로 this 키워드에 다른 값을 부여하게 함으로써 이를 구현했다.

<br>

#### JS를 처음 접하는 분들은 흔히 메서드를 '객체의 프로퍼티에 할당된 함수'로 이해한다.
- 이 말은 반은 맞고, 반은 틀리다.
- 어떤 함수를 객체의 프로퍼티에 할당한다고 해서, 그 자체로서 무조건 메서드가 되는 것이 아니다.
  - 객체의 메서드로서 호출할 경우에만 메서드로 동작한다.
```js
var func = function (x) {
  console.log(this, x);
};
func(1); // Window { ... } 1

var obj = {
  method: func,
};
obj.method(2); // { method: f } 2
```
- 1번째 줄에서 func라는 변수에 익명함수를 할당했다.
- 4번째 줄에서 func를 호출했더니 this로 전역객체 window가 출력되었다.
- 9번째 줄에서는 같은 함수를 변수에 할당하고 호출했더니 다른 값이 나왔다.
- 원래의 함수는 그대로인데 변수로 호출하는 경우와 그냥 호출한 경우에 this가 달라졌다.

#### 그렇다면, 함수로서의 호출과 메서드로서의 호출은 어떻게 구분할까?
- 그냥 함수 앞에 점이 있는지 없는지 여부만으로 구분할 수 있다.
- 당연히 대괄호 표기법도 메서드로 호출한 것이다.

<br>

#### 메서드 내부에서의 this
- this에는 호출한 주체에 대한 정보가 담긴다.
- 어떤 함수를 메서드로서 호출한다면, 호출 주체는 앞에 명시된 객체일 것이다
- 점 표기법으로 계속해서 체이닝한다면 마지막 점 앞의 객체가 this가 되는 것이다.
- 그렇다면 메서드 내부에서의 this는 정확히 내가 생각한 대로 동작하네

### 3-1-3 함수로서 호출할 때, 그 함수 내부에서의 this
#### 함수 내부에서의 this
- 어떤 함수를 함수로서 호출할 경우에는 this가 지정되지 않는다.
- 메서드로 실행한 것이 아니기 때문
- 이 경우에는 전역 객체를 바라본다.
- 더글라스 크락포드는 이를 설계상의 오류라고 지적한다.
  - 왜지?

#### 메서드의 내부함수에서의 this
- 메서드 내부에서 정의하고 실행한 함수에서의 this는 자바스크립트 초심자들이 this에 관해 가장 자주 혼란을 느끼는 지점 중 하나이다.
```js
var obj1 = {
  outer: function () {
    console.log(this);
    var innerFunc = function () {
      console.log(this);
    };
    innerFunc(); //(2)

    var obj2 = {
      innerMethod: innerFunc,
    };
    obj2.innerMethod(); //(3)
  },
};
obj1.outer(); //(1)
```
- 이 예시에서 각 로그에 찍히는 내용은 아래와 같다.
  1. obj1
  2. 전역객체(window)
  3. obj2
- 결론은 this 바인딩에 대해서는 함수를 실행하는 당시의 주변 환경(메서드 내부, 함수 내부 등)은 중요하지 않다.
- 오직 함수를 호출하는 구문 앞에 점 또는 대괄호 표기가 있는지 없는지가 중요하다.

#### 메서드의 내부 함수에서의 this를 우회하는 방법
- 위처럼 그냥 점, 대괄호만 확인하면 this에 대한 구분은 명확히 할 수 있다.
- 그러나, this라는 단어가 주는 인상과는 솔직히 다르다.
  - 호출 주체가 없을 때는, 자동으로 전역객체를 바인딩하지 않고 호출 주변 환경의 this를 그대로 상속받아 사용하면 더 자연스럽고 좋을 것이다.
  - 그래야 스코프 체인과도 일관성이 있다.

#### 그렇다면 어떻게 우회해서 사용해야할까?
- ES5까지는 자체적으로 내부함수에 this를 상속할 방법이 없다.
  - 그러나, 대표적으로 변수를 활용한다면 가능하다.
```js
var obj = {
  outer: function () {
    console.log(this); // (1) { outer: f }
    var innerFunc1 = function () {
      console.log(this); // (2) Window { ... }
    };
    innerFunc1();

    var self = this;
    var innerFunc2 = function () {
      console.log(self); // (3) { outer: f }
    };
    innerFunc2();
  },
};
obj.outer();
```

#### ES6에서는 함수 내부에서 this가 전역객체를 바라보는 문제를 보완하고자 this를 바인딩하지 않는 화살표 함수를 새로 도입했다.
- 화살표 함수는 실행 컨텍스트를 생성할때 this 바인딩 과정 자체가 빠져서 상위 스코프의 this를 그대로 활용할 수 있다.
- 그래서 웬만하면 화살표 함수를 쓰라고 하는건가?

### 3-1-4 콜백 햄수 호출 시 그 함수 내부에서의 this
- 콜백 함수란?
  - 함수 A의 제어권을 다른 함수 B에게 넘겨주는 경우 함수 A를 콜백함수라고 한다.
  - 이때 함수 A는 함수 B의 내부 로직에 따라 실행되며, this 역시 함수 B 내부 로직에서 정한 규칙에 따라 값이 결정된다.
  - 제어권을 받은 함수에서 콜백 함수에 별도로 this가 될 대상을 지정한 경우에는 그 대상을 참조하게 된다.
```js
setTimeout(function () {
  console.log(this);
}, 300); // (1)

[1, 2, 3, 4, 5].forEach(function (x) {
  // (2)
  console.log(this, x);
});

document.body.innerHTML += '<button id="a">클릭</button>';
document.body.querySelector('#a').addEventListener('click', function (e) {
  // (3)
  console.log(this, e);
});
```
- 1 : 전역객체
- 2 : 전역객체
- 3 : 클릭 이벤트에 관한 정보가 담긴 객체
### 3-1-5 생성자 함수 내부에서의 this
- JS는 함수에 생성자로서의 역할을 함께 부여했다.
- new 명령어와 함께 함수를 호출하면, 해당 함수가 생성자로서 동작하게 된다.
- 그리고 어떤 함수가 생성자 함수로서 호출될 경우 내부에서의 this는 곧 새로 만들 구체적인 인스턴스인 자신이 된다.
- 여기서의 this는 생성자 정의할때 java에서 쓰는 this와 동일하게 동작하네

## 명시적으로 this를 바인딩하는 방법
- 위에서 알아본 규칙대로 this가 부합하지 않는다면, 아래 방법들 중 하나이다.

<br>

### 3-2-1 call 메서드
- call 메서드는 메서드의 호출 주체인 함수를 즉시 실행하도록 하는 명령어이다.
- 함수를 그냥 실행하면 this는 전역객체를 참조하지만, call 메서드를 이용하면 임의의 객체를 this로 지정할 수 있다.

### 3-2-2 apply 메서드
- apply 메서드는 call 메서드와 기능적으로 완전히 동일하다.
- apply 메서드는 두번째 인자를 배열로 받아 그 배열의 요소들을 호출할 함수의 매개변수로 지정한다는 점만 다르다.

### 그 외에 call / apply 메서드, bind 메서드 등으로 JS를 더욱 다채롭게 활용할 수 있다.
