# 3장. this

this 는 실행 컨텍스트가 생성될 때 결정되는 값이다.
→ 실행 컨텍스트는 함수를 호출할 때 결정, 즉 this 도 함수를 호출할 때 결정된다.

→ 상황에 따라 this 가 보는 값이 달라진다.

## 1. 상황에 따라 달라지는 this

### 1) 전역 공간에서의 this

- 브라우저 → `window`, Node.js → `global`
- 전역 변수를 선언하면 브라우저는 이를 전역 객체의 프로퍼티로 할당한다.
- _실행 컨텍스트는 변수를 수집해서 L.E 의 프로퍼티로 저장합니다.
  이후 어떤 변수를 호출하면 L.E 를 조회해서 일치하는 프로퍼티가 있을 경우 그 값을 반환합니다.
  → 전역 컨텍스트에서 L.E 는 전역 객체를 참조한다.
  → 그래서 전역 변수가 전역 객체의 프로퍼티로 저장되는 것._

```bash
var a = 1;
// 스코프 체인에서 a 검색 > .. > 전역 스코프의 L.E (=전역 객체) 에서 프로퍼티 a 를 반환
console.log(a); // 1
```

```bash
// 둘은 같은 방식
var a = 1; ***
window.a = 1 ;
```

전역 변수 선언 vs 전역 객체 프로퍼티로 선언의 차이
→ 전자는 해당 프로퍼티의 `configurable === false` 로 정의한다.
→ 전자는 호이스팅이 되지만, 후자는 되지 않는다.

<함수 vs 메서드>

- 함수 : 독립적으로 실행, 특정 객체와 무관하게 동작함
- 메서드 : 객체에 속해있고, 자신이 호출한 객체 데이터를 변경함
  ```bash
  // 메서드
  text = "hello"
  result = text.upper()

  // 함수
  const foo = () => {
  ..
  }
  ```
  - 함수를 객체 프로퍼티에 할당한다고 해서, 그 자체로서 메서드가 되지 않는다.
    **객체의 메서드로 호출**한 경우에만 메서드로 동작하고, 그 외에 경우에는 함수로 동작한다.

### 2) 함수 vs 메서드 내부에서의 this

- 함수와 메서드의 차이
  - 함수 : 그 자체로 독립적인 기능을 수행한다.
  - 메서드 : 자신을 호출한 대상 객체에 관한 동작을 수행한다.
    → 객체의 메서드로서 호출한 경우에만 메서드로 동작하고, 그렇지 않으면 함수로 동작함
- 함수와 메서드로서 호출 구분 : 앞에 `.` 이 있는지의 여부
  (앞에 객체가 명시되있는지의 여부)
- 함수 내부에서의 this → 전역 객체
  _실행 컨텍스트를 활성화할 당시, this 가 지정되지 않은 경우 this 는 전역 객체를 바라봄
  → 함수에서의 this 출력이 `window` 가 나오는 이유_
- ES6 부터는 함수 내부에서 this 가 전역 객체를 바라보는 문제를 해결하기 위해, 화살표 함수를 도입했다.
  (실행 컨텍스트를 생성할 때 this 바인딩 과정 자체가 빠져서, 상위 스코프 this 를 그대로 활용할 수 O)

### 3) 콜백 함수 내부에서의 this

```jsx
function handleClick() {
  console.log(this); // 클릭된 버튼
}
// this : button1
button1.addEventListener("click", handleClick);
// this : button2
button2.addEventListener("click", handleClick);
```

- 콜백 함수도 함수. 즉, this 가 전역 객체를 참조하지만 제어권을 받은 함수에서 콜백 함수에 별도로 this 가 될 대상을 지정한 경우 그 대상을 참조한다. _(button1, button2 를 지정, this 는 이 둘을 참조)_
  - addEventListner 가 handleClick 의 제어권을 받는다.
  - 이벤트 발생 시, this 를 button 으로 지정한 상태
  - myFunc 안에서 `this`= button 이 된다.

### 4) 생성자 함수에서의 this

- 함수와 생성자와의 관계
  - new 명령어와 함께 함수를 호출하면, 그 함수는 생성자로서 동작한다.
    함수가 생성자 함수로서 호출된 경우 내부 `this` 는 새로 만들 **구체적인 인스턴스** 자신이 된다.
- 함수가 인스턴스를 만드는 과정
  1. `__proto__` 프로퍼티가 있는 인스턴스 생성
     (생성자의 prototype 프로퍼티를 참조)
  2. 미리 준비된 속성을 인스턴스( `this` ) 에 부여

→ 여기까지가 상황에 따라 this 가 달라져서, 그 this 가 무엇인지 우리가 파악해야 하는 경우.
이 다음부터는 명시적으로 this 를 바인딩하는 방법

## 2. 명시적으로 this 바인딩하기

### 1. call( )

```jsx
const func = function (a,b,c) {
..
}
// func 함수를 즉시 실행
func.call({x:1}, 1,2,3);
// 1. {x:1} 을 this 로 바인딩
// 2. 이후 인자들을 func 함수의 매개 변수로 전달
```

[함수.call](http://함수.call)( ) 를 이용하면 임의 객체를 this 로 지정할 수 있다.
(1번째 매개변수로 전달하는 객체)

### 2. apply( )

```jsx
// ['Hello', '!'] 가 각각 greeting, punctuation 로 전달
// 펼쳐서 전달
function greet(greeting, punctuation) {
  // 출력 : Hello, Alice !
  console.log(greeting + ", " + this.name + punctuation);
}

const person = { name: "Alice" };

greet.apply(person, ["Hello", "!"]);
```

기능적으로는 call( ) 와 동일하지만, 두 번째 인자를 배열로 받아 매개변수로 펼쳐서 전달한다는 차이가 있다.

### 3. bind( )

bind 뒤에 오는 객체가 this 로 명시적으로 고정 된다.

### 4. 화살표 함수 - this

```jsx
const person = {
  name: "철수",

  // 일반 함수: 자기만의 this 있음
  // 호출 대상에 따라 this 가 달라짐
  // person.sayHi -> 호출 대상은 person
  sayHi: function () {
    console.log("안녕, " + this.name);
  },

  // 화살표 함수는 선언된 위치의 바깥 this 를 사용
  // person 객체 바깥 = 전역 범위 = 전역 범위의 this 는 window
  // window.name 은 undefined
  sayBye: () => {
    console.log("잘가, " + this.name);
  },
};

person.sayHi(); // "안녕, 철수" ✅
person.sayBye(); // "잘가, undefined" ❌
```

### 5. 콜백 함수 내에서의 this

- 일반 함수든, 화살표 함수든 인자로 전달된다면 콜백 함수
- 보통 this 가 window
- 콜백 함수를 인자로 받는 메서드 중 일부는 this 로 지정할 객체를 인자로 지정할 수 있다. 이런 방식으로 콜백 함수 내부에서의 this 를 원하는 데로 변경할 수 있다.
  (배열.forEach( ) 는 콜백함수, this 로 쓸 객체를 인자로 받음)
      ```jsx
      // thisArg X -> this = window
      // thisArg O -> 콜백 함수 내의 this 를 명시적으로 지정
      배열.forEach(콜백함수, thisArg = this로쓸객체);
      ```

      - 배열 메서드가 thisArg 를 지원하는 이유
      : 배열 메서드는 객체 데이터를 처리해야 하는 경우가 많기 때문, 그래서 this 를 지정해서 객체의 데이터를 가공한다.
